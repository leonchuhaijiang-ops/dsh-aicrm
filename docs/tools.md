# 模型工具清单

插件向 DSH 注册 **15 个模型工具**。它们在对话里被模型调用，读写的都是你自己数据目录里的两张 Excel 表 —— 不需要另外开服务、不需要数据库。

一句话分工：

| 工具 | 干什么 | 读/写 |
|---|---|---|
| `sales_plan` | **今日作战队列**：今天该打哪些电话（首次触达 + 今日跟进），带原因与话术 | 只读 |
| `sales_brief` | **AI 每日工作台**：我已做完的 / 今天要你动手的 / 要你点头的 1 件 + 飞轮观察 | 只读 |
| `sales_tasks` | 待跟进清单（逾期 / 今日到期 / 未来 N 天临期 / 待定无排期） | 只读 |
| `sales_campaign` | **周战役**：电话批 / 微信批 / 培育批，各带完整话术；纯派生不写盘 | 只读 |
| `sales_view` | 单个客户全景（档案 + 流水 + 联系人 + 用量事实） | 只读 |
| `sales_sop` | 单个客户 SOP 时间轴（13 段漏斗 + 2 个出口） | 只读 |
| `sales_next` | 单个客户**作战卡**：现在最该做的一件事、为什么是今天、怎么开口 | 只读 |
| `sales_live` | 通话中**实时接话**：客户刚说了什么 → 现在该接哪句 | 只读 |
| `sales_summary` | 汇总统计（总数 / 状态 / 等级 / 触达 / 阶段 / 流水） | 只读 |
| `sales_digest` | **周复盘**：一段时间的两表现算（新增、推进、结论、黑洞、转介绍、瓶颈） | 只读 |
| `sales_flywheel` | **飞轮体检**：13 环人数/转化/停滞 + 售后与转介绍环；也可记一笔转介绍 | 读 + 写 |
| `sales_enterprise` | 企业级轨：候选盘点 / 单客户「一段三件事」/ 记企业级台账 | 读 + 写 |
| `sales_log` | **记一次跟进**（写流水 + 回写主表），是日常唯一的高频写入口 | 写 |
| `sales_settle` | 给客户**点名结论**（沉默/暂缓/无法联系/终止/成交），单个或批量 | 写 |
| `sales_contract` | 合同台账全生命周期（含生成 .docx、规则初审） | 读 + 写 |

> 全部工具名以 `sales_` 开头。模型只有在真的需要动数据时才调用它们；你也可以直接说人话，模型会自己选工具。

## 1. 典型用法（照着说就行）

### 每天开工

```text
今天该给谁打电话？
```

模型会先 `sales_plan`（队列），需要更细的执行清单再 `sales_brief`（工作台）。今天的电话量、长尾批量触达话术、每个客户为什么被排进队列，都在回执里。

### 一周排期

```text
把下周的三批触达排出来
```

→ `sales_campaign`。电话批只挑手机号合法的高优先客户，微信批走长尾，培育批只轻触达、不催单。三批互不占额度。

### 跟一个客户

```text
把<客户>的情况给我理一下 / 下一位客户我怎么跟
```

顺序通常是 `sales_view`（全景）→ `sales_sop`（走到哪一段）→ `sales_next`（作战卡：开口怎么说、打不通怎么办）。通话中把客户刚说的话丢给 `sales_live`，它给 1–3 条「你现在该接的那句」。

### 记跟进（每次通话后）

```text
刚跟<客户>通了电话，聊了…… 下次周五再跟
```

→ `sales_log`。它会往流水表追加一条，同时回写主表的排期、阶段、等级等。**每次跟进后都应该调它**，否则下次排期还是旧的。

### 给客户一个结果

```text
这个客户先不跟了，明年 3 月预算下来再说
```

→ `sales_settle`，结论=暂缓，锚点=「明年3月预算」。批量清黑洞时可以传多个客户 ID 一次点名。

### 周复盘

```text
上周到底发生了什么？
```

→ `sales_digest`。默认回看 7 天，只读现算，不写盘、不缓存。

### 合同

```text
帮我建一份<客户>的合同，标品，三万六
```

→ `sales_contract`，`action=save` 存要素，`action=generate` 出 .docx（落在 `<数据目录>/合同/`），`action=review` 做规则初审。**文件只在本机生成、只在本机读取，不上传。**

## 2. 参数速查

### `sales_plan` / `sales_brief` / `sales_summary`

无参数。

### `sales_tasks`

| 参数 | 类型 | 说明 |
|---|---|---|
| `days` | number | 窗口天数，默认 7，范围 1–90 |

### `sales_view` / `sales_sop` / `sales_next`

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | string，**必填** | 客户ID，或公司名 / 手机号关键字（模糊匹配） |

### `sales_live`

| 参数 | 类型 | 说明 |
|---|---|---|
| `text` | string，**必填** | 客户刚说的话（本机转写文本，建议最近 60 秒） |
| `id` | string | 客户ID / 公司名 / 手机号；不传就只按话术库给通用应对 |
| `limit` | number | 最多返回几条，默认 3，上限 5 |

### `sales_campaign`

| 参数 | 类型 | 说明 |
|---|---|---|
| `phone` / `wechat` / `nurture` | number | 三批各自条数上限，默认 20，上限 50 |

### `sales_digest`

| 参数 | 类型 | 说明 |
|---|---|---|
| `days` | number | 回看天数，默认 7，上限 90（窗口含今天） |
| `date` | string | 窗口结束日 `YYYY-MM-DD`，默认今天 |

### `sales_log`（参数最多，但日常只需要前几个）

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | string，**必填** | 客户ID |
| `method` | string | 方式：`电话` / `微信` / `上门` / `短信` / `合同` / `官网申请` / `其他` |
| `type` | string | 类型：`首触` / `试用回访` / `高意向跟进` / `老客服务` / `客户反馈` / `策略调整` / `放弃跟进` / `数据整理` |
| `stage` | string | 把客户推进/回退到该 SOP 段；不传 = 停留。旧叫法自动归一。**归不进 13 段/出口的写「其他跟进记录」**：阶段留空、主表当前阶段不动，看板归到「其他跟进记录」 |
| `date` | string | 跟进日期 `YYYY-MM-DD`。**不传就留空**，不会自动填今天 |
| `what` | string | 沟通内容 |
| `react` | string | 对方反应 |
| `nextAction` | string | 下一步动作 |
| `nextDate` | string | 下次时间 `YYYY-MM-DD`；传 `待定` = 清空排期；**整个参数不传 = 保持主表原排期不变** |
| `nextMethod` | string | 下次方式 |
| `clearNext` | boolean | 等价于 `nextDate=待定` |
| `status` | string | `跟进中` / `挂起` / `重点跟进` / `挂起冷备` / `已闭环` / `待首触`（后三类挂起态必须有据，见下） |
| `level` | string | `SS`/`S`/`A`/`B`/`C`；传 `-` 清空为未定级。**通常不用传**，等级会跟着分类自动归一 |
| `name` / `company` / `phone` / `city` / `wechat` | string | 顺手回写主表对应列（`phone` 必须是 11 位、1 开头，且不能与别的客户重复） |
| `expire` / `reg` | string | 到期时间 / 注册时间，`YYYY-MM-DD`（也接受 Excel 日期序列号） |
| `note` | string | 追加到主表备注的一句话 |

`nextDate` 的三态很关键，别搞混：

| 你传了什么 | 结果 |
|---|---|
| `"2026-05-20"` | 排期写成这天 |
| `"待定"` / `clearNext:true` | **清空**排期，客户进「待定跟进」区，不再显示到期 |
| 什么都不传 | 主表原排期**原样不动**（不是清空） |

### `sales_settle`

| 参数 | 类型 | 说明 |
|---|---|---|
| `kind` | string，**必填** | `沉默等需求`(→挂起) / `暂缓`(→挂起冷备) / `无法联系`(→挂起冷备+出口) / `推进终止`(→已闭环+出口) / `成交签约`(→已闭环+成交) |
| `id` | string | 单个客户 ID（与 `ids` 二选一） |
| `ids` | string[] | 批量点名，同一个结论 + 同一个锚点，上限 50 |
| `anchor` | string | 复查锚点：日期 `YYYY-MM-DD` 或一个信号（如「客户新项目立项」）。`沉默等需求` / `暂缓` **必填** |
| `stuckAt` | string | 停在哪个 SOP 段，默认取主表当前阶段 |
| `note` / `date` | string | 补充说明 / 发生日期 |

### `sales_enterprise`

| 参数 | 类型 | 说明 |
|---|---|---|
| `id` | string | 给 id = 单客户推进建议；不给 = 候选盘点 |
| `pool` | boolean | 强制候选盘点 |
| `facts` | object | **记台账**：只认 `决策人` / `预算口` / `资料权属` / `安全要求` / `试点范围`，至少一项非空 |
| `limit` | number | 候选盘点每类条数，默认 20，上限 50 |
| `date` | string | 台账日期 |

注意：记台账**只落流水留痕，不动主表阶段** —— 阶段推进要显式走 `sales_log(stage=…)`。

#### 归不进 SOP 节点的跟进放哪

不是每次跟进都能对上 13 段里的一段（比如老数据没写阶段、随手记的行业闲聊、跨段的杂事）。这类记录不要硬塞进某一段：

- 写日志时传 `stage: '其他跟进记录'`（也认 `其他` / `未归类`）→ 流水「阶段」留空，**主表当前阶段不动**；
- 看板 SOP 面板底部归到「其他跟进记录」；`sales_sop` 返回里对应 `unlabeled` 字段（带 `unlabeledLabel`）；
- 老数据里「阶段」本来就是空的记录，同样落这个桶，不会丢。

**这套规则对每一个有跟进记录的客户都生效**（不是某个客户的特殊处理）：SOP 面板标题下会显示「共 N 条跟进：段内 x · 其他跟进记录 y」，两者相加就是该客户的全部跟进结果。

想知道全库有没有客户「记录对不上」，跑只读审计：

```bash
npm run audit                       # = node scripts/sop-audit.mjs
npm run audit -- --problems         # 只看对不上的客户
```

它逐客户核对 `跟进条数 = 段内 + 桶`，对不上就列客户 ID；顺带列出「有记录但主表当前阶段为空」的客户（这类客户补一次带 `stage` 的跟进即可把当前阶段推上去）。

历史记录想尽量进段，可以跑补阶段脚本（**默认只看不写**）：

```bash
npm run backfill                    # dry-run，打印可补清单
npm run backfill -- --apply         # 真写（先自动备份两张 xlsx）
npm run backfill -- --infer content --apply   # 再启用内容关键词判段（批量导入记录容易误判，慎用）
```

默认只认「类型 → 阶段」硬映射（首触→客户触达、试用回访→产品演示、老客服务→成交签约、放弃跟进→推进终止），判不出来的一律留桶——**不硬猜**：批量导入的「数据整理/策略调整」记录里常同时出现"报价/合同/签约"等词，按关键词判会把没进过漏斗的客户伪造成已报价/已成交，污染漏斗统计。

### `sales_flywheel`

| 参数 | 类型 | 说明 |
|---|---|---|
| `ring` | string | 只看某一环（13 段任一），不传 = 全体检 |
| `referral` | boolean | 记一笔转介绍留痕 |
| `by` / `to` | string | 介绍人 / 被介绍人（`referral` 模式**必须成对**） |
| `note` / `date` | string | 补充说明 / 日期 |

### `sales_contract`

`action` 必填，共 13 个动作：

| `action` | 作用 | 关键参数 |
|---|---|---|
| `list` | 台账列表（含到期/红点） | — |
| `get` | 看单份合同 | `合同ID` |
| `save` | 存合同要素（新建或更新） | `合同ID`? / `客户ID` / `类型` / `金额` / `税率` / `付款节点` / `签署日` / `生效日` / `到期日` … |
| `status` | 改状态 | `合同ID` / `状态`（`待签`/`已签`/`履行中`/`已完成`/`已归档`/`已作废`） |
| `sign` | 签署（默认同时把客户推进到「成交签约」） | `合同ID` / `日期` |
| `pay` | 记一个付款节点 | `合同ID` / `节点名` / `日期` / `备注` |
| `audit` | 落初审留痕 | `合同ID` / `结论` / `风险` / `模式` / `免责` |
| `file` | 落文件记录；`下载:true` 时读回字节给看板保存 | `合同ID` / `路径` / `名` / `字节` / `sha256` |
| `archive` | 归档 | `合同ID` |
| `void` | 作废（**必须写原因**） | `合同ID` / `原因` |
| `templates` | 列出可用的生成模板 | — |
| `generate` | 在本机生成 `.docx` | `合同ID` / `模板` / `要素` |
| `review` | 规则初审（高/中/低风险 + 免责声明） | `合同ID` / `模式` / `保存` |

> 合同初审判定只是**规则提示**，不构成法律意见。正式签署前请让法务/律师过一遍。

## 3. 三条写入口径（看代码也一样）

1. **日期一律 `YYYY-MM-DD`**。模型不会替你猜「今天」——`sales_log.date` 不传就是空；`sales_settle.date` 不传才默认今天。
2. **挂起态必须有据**。`sales_log(status='挂起'|'挂起冷备'|'已闭环')` 要求：该客户已有【结论】流水，**或**本次同时把阶段推到出口。否则写入口直接拒绝。想正常停跟一个客户，用 `sales_settle` 并给锚点。
3. **等级跟着分类走**。状态/阶段一变，写入口会把等级归一到该分类对应的等级，回执里会说这次归一了什么。手工填 `level` 一般不需要。

## 4. 看板里的 AI 按钮 vs 模型工具

模型工具是给对话里的 agent 用的。看板上的「🧠 生成」类按钮（实时话术、整段文案、作战卡、今日工作台、周复盘、合同复核）走的是另一条路：`POST /sales/ai`，**点了才调模型**，有硬超时，失败就静默回落到规则版。

两条路都经过同一个 `dsh/ai.js` 出口，都遵守同一套脱敏与台账规则。区别只是：工具回执给模型读，按钮回执给页面渲染。
