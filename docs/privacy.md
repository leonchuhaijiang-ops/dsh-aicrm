# 隐私与数据边界

> 一句话：**客户数据只存在你指定的那个目录里**。插件本身没有账号、没有云同步、没有埋点；唯一的出网口是「调用 DSH 宿主里的模型」，而这一步带字段级脱敏。

这一页写得比较直白，包括**做不到的地方**——因为「本地优先」不等于「绝对不出网」，含糊表述会害你。

## 1. 数据在哪

| 数据 | 位置 | 出网？ |
|---|---|---|
| 客户主表 / 流水表 | `<数据目录>/销售客户-*.xlsx` | 否 |
| 合同正文 | `<数据目录>/合同/*.docx` | 否 |
| 合同台账 / 首访清单 / 用量快照 | `<数据目录>/*.json` | 否 |
| AI 调用台账 | `<数据目录>/logs/ai-calls.log` | 否 |
| 营销资料库 | `<数据目录>/营销资料库/` | 否（只被本地词法检索读） |
| 插件配置 | `<home>/.dsh/sales.config.json` | 否 |

插件**不写**任何其他位置：没有 AppData 缓存、没有临时上传目录、没有「匿名统计」。仓库里也不含任何客户数据（`npm run check-no-pii` 会扫）。

HTTP 端点（`/sales/*`）只监听 DSH 宿主自己的本机端口，不对外暴露；需要鉴权的是 DSH 那一层，插件不另设账号体系。

## 2. 唯一的出网口：模型调用

AI 功能（作战卡、实时话术、周复盘、合同复核……）需要调模型。这条路是这样的：

```text
插件 dsh/ai.js  →  DSH 宿主 ctx.llm  →  模型 provider
```

- 插件**不持有 API key**、**不自己发 fetch**、**不直连任何 provider**。密钥在 DSH 里，由宿主管理。
- 全插件只有 `dsh/ai.js` 一个文件允许出现 `llm.stream(`，其他文件想调模型必须 import 它。
- 默认 `ai.mode=session`：用你当前会话正在用的模型，**不会**因为装了插件而多一条数据通道。
- 想更保守：`ai.mode=local` 接本机模型（Ollama 等），客户数据就一步都不出本机，代价是效果弱、上下文短（见 [docs/configuration.md](./configuration.md)）。
- 语音：通话台的转写走 DSH 宿主提供的 `speechController`（语音输入 bundle），插件只把音频交给宿主、**自己不解析不转存不出网**。用哪个语音 provider 由你在 DSH 里配——选「本机转写」时音频不出本机；若你装的是云端语音 provider，那这一段音频会按那个 provider 的规则出网，**插件无法替它保证**。设置里 `features.speech=false` 可以整个关掉通话台。

### 发出去之前做了什么

`dsh/redact.js` 做**字段级脱敏**（A′ 档）：

| 字段 | 发出去的样子 |
|---|---|
| 姓名 / 联系人 | `<客户1\|设计院总工>`（带角色标签的占位符） |
| 公司 | `<单位1\|市政交通>`（带行业标签） |
| 手机 | `<电话1>` |
| 微信昵称 | `<微信1>` |

模型返回后再把占位符换回真实值，所以你看到的文案里是真人名真公司名，但**模型看到的是占位符**。同一段对话里重复出现的同一实体沿用同一个编号，模型仍能分辨「这是同一个人」。

### 脱敏遮不住什么（重要）

这是**字段级**脱敏，不是语义脱敏。以下内容会原样发给模型：

- 你写在 `沟通内容` / `对方反应` / `备注` 里的自由文本。如果里面提到「张总说他们下季度要报批」，那「张总」不会被遮——因为它不是结构化字段。
- 客户自己叙述的公司业务、项目名称、预算数字。
- 营销资料库里你放的任何内容（开 RAG 时会被检索出来发给模型）。

所以：**别把不该给模型看的东西写进备注栏**。真敏感的客户，就把 `ai.mode` 设成 `local`，或干脆只用规则版功能（不点 AI 按钮、不调用会触发模型的工具）。

## 3. 台账只记元数据

`<数据目录>/logs/ai-calls.log` 每次模型调用记一行，字段只有：用途（purpose）、模型、耗时、字数、成败。

**不记**客户原文、**不记**提示词、**不记**模型回答。日志超过上限会滚动截断。

## 4. 出网闸门（防 agent 自己把表传出去）

`dsh/egress-guard.js` 是一个纯函数、同步、fail-closed 的守卫，挂在 agent 的工具调用前。它拦 8 类动作：

| 规则 | 拦什么 |
|---|---|
| R-1 | `web_search` / `web_fetch` 的请求里带客户数据（表名、目录名、手机号、客户ID、邮箱） |
| R-2 | 命令行里的出网动词（`curl`、`wget`、`ssh`、`scp`、`nc`、`npm publish`、`git push`、`gh release`、`bitsadmin`、`certutil -urlcache`、`net use`、`robocopy`、`tftp`、`tar -c` 等） |
| R-3 | 出网动词 + 数据目录名同时出现 |
| R-4 | 参数解析不了 → **直接拒绝**（fail-closed，宁可误杀） |
| R-5 | 客户数据 + UNC 共享路径（`\\\\host\\share`） |
| R-6 | 编码混淆搬运（`-EncodedCommand`、超长 base64）与客户数据/出网动词同现 |
| R-7 | 客户数据 + 代码里的网络库 API（`fetch(`、`axios`、`requests.post`…） |
| R-8 | 搜索/抓取里同时出现「称呼式人名 + 公司名」（身份外泄） |

两种档位：默认 `balanced`；设 `SALE_EGRESS_MODE=strict` 更严（误杀也会更多）。

## 5. 它做不到什么（如实说）

1. **拦不住分两步走**：先把表复制成 `a.csv`，第二步再上传——只要第二步的命令里不含客户关键词，正则看不出来。
2. **拦不住脚本自己读表**：`pwsh` 跑一个不含客户关键词的脚本，脚本内部读 Excel 再上传，闸门看不到脚本内容。
3. **拦不住别的程序**：你机器上其他软件、后台同步盘、云 Office 客户端，插件管不着。
4. **模型厂商侧**：数据一旦发给 provider，怎么留存、是否用于训练，由 provider 的条款决定，插件无法控制。默认 `session` 档用的是你本来就在用的通道，但**这仍然是数据出本机**。
5. **DSH 自身遥测**：如果 DSH 开了会话遥测，那是 DSH 层的行为，不是本插件。需要的话在 DSH 的 profile 配置里自行关闭（`session-telemetry-otel: disabled`）。

**所以对外别这么说**：「数据绝不离开本机」。准确说法是：**客户数据只发给模型厂商这一条通道，其余一律不出本机；能不给就不给（最小必要 + 字段脱敏），不想给就切本机模型。**

## 6. 文件卫生（比代码更容易出事的地方）

- **不要**把数据目录放在 OneDrive / iCloud Drive / 坚果云 / WPS 云盘 / 任何同步盘里。同步客户端会在你写表的同时回写，轻则写锁冲突，重则把表改成半截。
- **不要**用在线 Office（网页版 Excel / WPS 云文档）打开这两张表——打开即上传。
- 用本机 Excel / LibreOffice 打开，编辑完保存关闭，再让插件写。
- 备份：定期把整个数据目录复制一份到本地另一块盘。仓库和云盘都不是备份方案。
- xlsx 是**明文**压缩包，任何能读你磁盘的人都能打开。需要更强保护就用全盘/目录加密（BitLocker、FileVault、VeraCrypt 之类）。

## 7. 合规提醒

- 表里存的是**个人信息**（姓名、手机号、微信）。收集和使用要有合法依据，遵守你所在地区的个人信息保护法规（如中国的《个人信息保护法》）：目的明确、最小必要、可删除、可更正。
- 如果模型 provider 在境外，把个人信息发过去可能构成**跨境提供**，需要你自行评估并履行相应义务。这也是 `local` 档存在的意义。
- 合同初审的结论是**规则提示**，不是法律意见；正式签署前应由法务/律师审阅。

## 8. 删除与导出

- **导出**：两张 xlsx 本来就是标准 Excel，直接用 Excel 打开另存即可；合同在 `合同/` 下。
- **删除**：删掉整个数据目录（含 `logs/`、`合同/`）即彻底删除。插件不保留副本。
- **卸载插件**：不影响数据目录。

## 9. 这个仓库与作者的数据是隔断的

- **仓库里只有工具**：全部源码 + 文档 + `templates/营销资料库/` 里 4 份**原创**示例语料。**没有**任何真实客户表、备份、日志、合同、配置档或密钥。作者自己跑数据用的目录在这台机器上另处，从不进 git。
- **git 历史也干净**：整个历史只保留少量提交（首版 + 文档修订），历史 diff 已逐条扫过手机号、邮箱、令牌、本机路径，无命中。
- **硬拦落盘**：`.gitignore` 挡住 `*.xlsx / *.csv / *.docx / logs/ / 备份/ / 快照/ / sales.config.json / .env`；本地 `pre-commit` 钩子（`npm run hooks` 安装）在提交前跑 `check-no-pii`；CI 里再跑一遍。两道闸门任一命中即失败。
- **不回传**：工具代码里没有遥测、没有上报端点、没有作者服务器；唯一出网口是**你自己配的模型厂商**（第 2 节）。作者拿不到你的任何数据，也没有地方接收。
- **别人用的时候**：各自的数据目录在自己机器上，初始化时由 `scripts/setup.mjs` 或看板向导现建空表；你装我装，数据互不相干。

你想自己核一遍：

```bash
npm run check-no-pii                                  # 当前工作区
git log --all -p | grep -nE "[0-9]{11}|ghp_|sk-[A-Za-z0-9]{16,}"   # 全历史
```

## 10. 发版前的仓库自检

```bash
npm run check-no-pii
```

扫手机号、邮箱、身份证、疑似 API key、本机绝对路径、私有品牌词；命中即非零退出。CI 里也跑这条——仓库是公开的，一次泄漏就是一次事故。
